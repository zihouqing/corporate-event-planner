# 老周 · 企业活动策划专家

一个在 **WorkBuddy** 上运行的 AI 专家（Agent），专做团建 / 年会策划。

它的核心不是"会写方案"，而是两条**不可跳过的硬闸门**：

> **预算先于场地，点位必须真实。**

---

## 为什么要做

AI 写活动策划，翻车永远翻在两个地方：

| 翻车方式 | 具体表现 |
|---|---|
| **钱算不过来** | 预算表看着漂亮，一到真实报价超支 30%。因为它是"先看中场地，再倒着凑预算" |
| **场地是假的** | 方案里写着"XX 国际会议中心"，一查根本不存在。模型把常见酒店品牌和城市名拼在一起，听起来极其合理 |

这两点恰好是**最贵的**——一个毁钱，一个毁信誉。所以这个专家把两件事做成了流程里的强制闸门，而不是提示词里的一句"请注意"。

## 三个设计决策

### 决策一：预算是闸门，不是参数

流程被固定成六个阶段，**顺序不可交换**：

```
需求澄清 → 预算骨架 → 候选生成 → 真实核验 → 单点对平 → 方案输出
```

如果用户跳过预算直接说"帮我找个别墅"，Agent 会拒绝并先要预算。理由很直白：**没有预算约束的候选生成，必然产出超支方案**。这是把行业里死亡率最高的错误路径从流程上掐断。

### 决策二：点位三态，❌ 禁止进正文

| 状态 | 判据 | 处置 |
|---|---|---|
| ✅ 已核验 | 相似度 ≥ 0.85，且通过子设施拦截 | 可进方案，附地址电话 |
| ⚠️ 待确认 | 0.60 ~ 0.85，或换牌 / 重名 | 可进方案，必须标注"需二次确认" |
| ❌ 查无此店 | < 0.60 | **禁止进入方案正文** |

三态是硬约束。降级路径（没有 API Key 时走搜索）也必须标注"搜索核验"，不许冒充 API 核验。

### 决策三：说明不确定性，而不是消灭它

酒店**房价拿不到**——这不是实现缺陷，是高德 POI 的真实数据边界（`biz_ext.cost` 只有餐饮类有值，酒店返回空）。所以住宿科目永远标"需询价"，绝不拿经验区间冒充报价。

餐饮人均反而可以回填真实值（实测：某自助餐厅 319 元/人）。**哪些数据可信、哪些必须标未确认**，写死在文档里。

## 技术实现

```
总预算 → 扣机动金 → 人均日成本 → 档位判定 → 科目配比 → 承载力校验
                                                              ↓
                    候选点位生成 → 高德 POI 核验 → ✅进方案 / ⚠️标注 / ❌剔除
```

两个可独立运行的 Python 脚本，无第三方依赖（只用标准库）：

| 脚本 | 职责 |
|---|---|
| `budget_calc.py` | 预算正推 / 反推、档位判定、科目配比、承载力计算，支持 JSON 输出 |
| `poi_check.py` | 高德 POI 搜索、名称相似度打分、三态判定、驾车距离、批量核验限流 |

### 关键算法：名称相似度打分

这是整个项目里**最容易出错、也最值得说**的部分。三道防线：

1. **归一化**：去括号、去分店后缀、繁简统一、全角转半角
2. **包含关系加权**：`万丽酒店` → `深圳湾万丽酒店` 加权到 0.88（简称对全称应放行）；反过来 `阿那亚社区礼堂` → 只命中 `阿那亚` 则按长度比**打折**（园区名不是场地）
3. **子设施拦截**：候选名剥掉设施后缀（洗手间 / 停车场 / 大堂 / 入口 / 电梯）后若与目标高度相似，直接压到 0.50 判 ❌

第 3 条来自一个真实事故，见下。

## 踩过的坑

这些都是**跑真实数据才暴露**的，光看代码看不出来。

### 坑 1：洗手间冒充酒店（最危险）

```
查询：深圳观澜湖度假酒店
规范名：深圳观澜湖度假酒店洗手间      ← 洗手间
结果：✅ 已核验
```

API 没返回酒店本体，只返回了它的**洗手间**，相似度 0.88 直接判通过。如果漏过去，方案里会写一家"存在"的酒店，实际查到的是厕所。

修复比想象的绕：不能只判前缀，因为 `观澜湖度假酒店(深圳店)-大堂` 归一化后开头是"观澜湖"，和"深圳观澜湖"对不上，还是会漏。

最终方案是**先剥设施后缀，再算剩余部分的相似度**。这样两种变体都能拦住，同时不影响 `xx酒店·宴会厅`、`xx酒店·燃自助餐厅` 这类**业务**子点位（0.88 正常通过）。

### 坑 2：隔壁酒店冒充自家宴会厅

`大梅沙京基海湾大酒店-会议厅` 被算成 `大梅沙京基洲际度假酒店` 的宴会厅——这俩是隔壁邻居，不是一家。

加了主体归属校验（最长公共子串占比），现在只认自家子点位。

### 坑 3：批量核验必挂

个人 Key 的 QPS 很低，连跑第 5 个点位就 `[10021] QPS 超限`。

加了请求间隔（默认 1 秒）+ 对频率类错误的退避重试。**批量核验是核心场景**，不做这个等于功能不可用。

### 坑 4：关于"人均消费"的错误判断

我一开始认为需要额外调用 `place/detail` 接口才能拿到人均消费，专门准备补 30 行代码。

实测打脸：`place/text` 带 `extensions=all` **本来就返回 `biz_ext` 字段**，不用另调接口。而且 `cost` 对酒店类是空的——省了一次调用，也纠正了一个错误认知。

**教训：猜测 API 能力之前先实测一次，比读文档更快。**

## 安装

### 前提

- WorkBuddy 桌面客户端
- Python 3（脚本零第三方依赖）

### 装到 WorkBuddy

1. 把 `corporate-event-planner` 文件夹放进：
   - Windows：`C:\Users\<用户名>\.workbuddy\plugins\marketplaces\my-experts\plugins\`
   - macOS：`~/.workbuddy/plugins/marketplaces/my-experts/plugins/`
2. 打开 WorkBuddy，新建任务，说：

   > 帮我注册刚放进 my-experts 的 corporate-event-planner 专家

3. 到 **专家 · 技能 · 连接器 → 专家 → 我的专家** 看到「老周」即成功

### 配高德 Key（点位核验需要）

需要**「Web 服务」类型**的 Key（不是「Web 端 JS API」——这是最常见的配置错误）。

申请：<https://console.amap.com> → 应用管理 → 创建应用 → 添加 Key → 服务平台选 **Web 服务**

配置（任选其一，优先级从上到下）：

```bash
# 1. 文件（推荐，免重启）
echo "你的32位key" > ~/.amap_key

# 2. 环境变量（需重启客户端）
setx AMAP_KEY "你的32位key"

# 3. 单次调用
python3 poi_check.py --name "深圳湾万丽酒店" --city 深圳 --key "你的key"
```

**仓库里不含任何 Key**，也不应该含。

没有 Key 也能用，此时降级为联网搜索核验，方案里会标注"搜索核验"——降级不算失败，但必须诚实标注。

## 自测

```bash
cd skills/event-budget-planning/scripts

# 预算正推：30 人 2 天 8 万
python3 budget_calc.py --total 80000 --people 30 --days 2 --type teambuilding --city-tier 1

# 预算反推：只给人均上限
python3 budget_calc.py --per-head 800 --people 40 --days 2 --type teambuilding --city-tier 3

# 低预算告警（会算出缺口并给最低可行总额）
python3 budget_calc.py --total 10000 --people 50 --days 2 --type teambuilding --city-tier 1

# 点位核验
python3 poi_check.py --name "深圳湾万丽酒店" --city 深圳

# 批量核验（每行 名称|城市）
python3 poi_check.py --batch venues.txt --interval 1.5

# 两点驾车距离
python3 poi_check.py --distance "113.93,22.52" "114.06,22.54"
```

`poi_check.py` 退出码：`0` 通过 / `1` 参数或网络错误 / `2` 无 Key 需降级 / `3` 查无此店。

## 数据口径与免责

- `references/budget-model.md` 中的数字是**行业经验区间**（2025–2026 中国大陆口径），用于搭骨架和判断合理性，**不是报价承诺**
- 正式方案必须用核实价格回填重算，输出中注明"参考价，以销售正式报价为准"
- 酒店房价高德不提供，**必须询价**
- 点位核验保证"该名称在真实地图数据中存在"，**不保证**营业状态、档期、宴会厅容量——这些必须电话确认（文档里作为 L4 层级单独列出）
- 使用高德 API 需遵守其服务条款与配额限制
