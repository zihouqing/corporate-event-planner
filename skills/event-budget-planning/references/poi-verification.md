# 点位核验规范

> 本文件解决一个问题：**怎么确认一家酒店/场地真的存在、真的在营业、真的装得下这么多人。**
> 核验不通过的点位不许进方案正文。这是本专家不可让渡的底线。

---

## 一、为什么要做这一步

策划方案最常见的失效方式不是算错钱，是**写了一个不存在或已经关门的场地**。原因通常是：

- 模型凭印象编名字（"XX 国际会议中心"听起来很合理，实际没有）
- 酒店已改名/换牌（原"喜来登"改成"某某酒店"）
- 分店混淆（同一品牌在同一个城市有 8 家，报价差一倍）
- 主体存在但宴会厅早已改造成办公区

所以核验的目标有四个层次，缺一不可：

| 层次 | 要确认什么 | 失败后果 |
|---|---|---|
| L1 存在性 | 这个主体真实存在 | 方案作废 |
| L2 地址 | 地址与城市/区对得上 | 客户找不到 |
| L3 营业状态 | 目前仍在营业 | 到场发现关门 |
| L4 承载力 | 有对应容量的厅/房/位 | 装不下人 |

L1-L3 靠脚本或搜索能确认，**L4 必须查酒店官网的宴会厅信息或打电话**，搜索往往查不到。做不到 L4 就标 ⚠️ 待确认。

---

## 二、核验三态（强制标注）

| 标记 | 判定条件 | 处理方式 |
|---|---|---|
| ✅ **已核验** | L1+L2+L3 全部确认，且有可追溯来源 | 进方案正文，附来源与日期 |
| ⚠️ **待确认** | L1+L2 确认，L3 或 L4 存疑 | 进正文，但必须同时列入「待确认清单」 |
| ❌ **查无此店** | 搜索无结果 / 名称对不上 / 确认停业 | **禁止进正文**，只能进「已排除」附注并写原因 |

判定时宁可降级，不可升级。**没查到就是 ⚠️，不是 ✅。**

## 三、方式 A：高德 POI API（首选）

### 3.1 Key 准备

- 类型必须是 **「Web 服务」**（不是「Web 端 JS API」，也不是「Android/iOS」）——这是最常见的坑
- 查找顺序：`--key` 参数 → 环境变量 `AMAP_KEY` → 密钥文件 `~/.amap_key` 或 `~/.workbuddy/amap_key`
- 不要把 Key 硬编码进脚本，也不要提交到仓库
- 免费额度以高德控制台「配额管理」页面显示的为准

### 3.2 调用

```bash
python3 scripts/poi_check.py --name "深圳湾万丽酒店" --city 深圳
python3 scripts/poi_check.py --batch venues.txt        # 每行：名称|城市
python3 scripts/poi_check.py --distance "113.93,22.52" "114.06,22.54"
```

脚本内部走两个接口：

| 用途 | 接口 | 关键参数 |
|---|---|---|
| 关键字搜索 | `/v3/place/text` | `keywords`, `city`, `citylimit=true`, `offset=10`, `extensions=all` |
| 驾车路径 | `/v3/direction/driving` | `origin=lng,lat`, `destination=lng,lat`, `extensions=base` |

### 3.3 返回字段怎么读

| 字段 | 含义 | 注意事项 |
|---|---|---|
| `status` | `1` 成功 / `0` 失败 | 失败时看 `info` 和 `infocode` |
| `count` | 命中条数 | `0` 不等于不存在，可能是关键词写法不对 |
| `pois[].id` | POI 唯一编号 | 可作为方案里的稳定引用 |
| `pois[].name` | 规范名称 | 与你写的名字做相似度比对 |
| `pois[].address` | 详细地址 | 核对区名（`adname`）是否与你说的片区一致 |
| `pois[].location` | `经度,纬度` | 用于算距离，注意是「先经后纬」 |
| `pois[].tel` | 电话 | 可能为空，空不代表不存在 |
| `pois[].typecode` | 业态码 | 住宿相关通常以 `1001` 开头（宾馆酒店） |
| `pois[].cityname` | 所属城市 | 核对是否跨市（环京环沪常混） |

### 3.4 名称匹配度

脚本用字符串相似度给每个命中项打分（0-1），并给出判定：

| 相似度 | 判定 | 处理 |
|---|---|---|
| ≥ 0.85 | 高度一致 | 视为同一主体 |
| 0.60-0.85 | 疑似 | 需人工核对地址，标 ⚠️ |
| < 0.60 | 不匹配 | 视为查无此店，换关键词重试一次后淘汰 |

**关键词写法建议**：用「品牌 + 具体地名」而不是完整全称。查"深圳湾万丽酒店"若 0 结果，试"万丽 深圳湾"、"深圳湾 万丽酒店"。**允许重试两次，两次都查不到就是查无此店。**

### 3.5 评分与消费字段（`extensions=all` 已自带，不用另调 detail）

`place/text` 带 `extensions=all` 时每条 POI 都带 `biz_ext`，可直接解析，**不需要再调 `/v3/place/detail`**：

| 字段 | 含义 | 实测情况（2026-10 深圳） |
|---|---|---|
| `rating` | 用户评分 | 酒店、餐厅都有值（4.5 / 4.6） |
| `cost` | 人均消费（元） | **餐饮有值**（燃自助餐厅 319.00）；**酒店返回空** |
| `star` | 星级 | 实测为空，不可依赖 |
| `lowest_price` | 最低价 | 实测为空 |

**结论，直接决定方案怎么写**：

1. **餐饮科目可以用 `cost` 回填**，这是接口里唯一能拿到的真实价格，可信度高于经验区间。
2. **住宿房费拿不到**。酒店 `cost`/`star`/`lowest_price` 全空，房费必须走官网、OTA 或电话询价。方案里写"房价需询价"，不许拿经验区间冒充实价。
3. **评分只作排序辅助**，不能替代容量和报价核验。4.8 分的酒店也可能宴会厅早已改造成客房。

### 3.6 宴会厅子点位

同一个酒店常会有一条 `酒店名·宴会厅` 或 `酒店名-会议厅` 的独立 POI。脚本会把它单独拎出来作为 **L4 承载力核验线索**——直接打这个电话问桌数，比打总机快。

注意：只认**同主体**的子点位。隔壁"XX 京基海湾大酒店-会议厅"不属于"XX 京基洲际度假酒店"，脚本用最长公共子串占比把这种邻居挡掉了。

## 四、方式 B：搜索降级（无 Key 时）

脚本退出码 2 = 无 Key。此时改用搜索，**必须在方案里标注"搜索核验"**，不能冒充 API 核验。

### 4.1 查询式（至少两条，互相印证）

1. `"<酒店全名>" <城市> 官网`
2. `"<酒店全名>" <城市> 地址 电话`
3. `<城市> <区域> 宴会厅 <桌数>人`（找场地时用）

### 4.2 交叉验证要求

至少要拿到**两个独立来源**指向同一地址，才算 L1+L2 通过：

| 来源类型 | 可信度 | 说明 |
|---|---|---|
| 酒店集团官网 / 官方小程序 | 高 | 最优，通常含宴会厅面积与桌数 |
| 高德/百度地图网页版 | 高 | 有地址和电话，可点开看是否"营业中" |
| 携程 / 美团 / 飞猪 | 中 | 有房型和点评，可判断是否在营 |
| 企业官网新闻 / 公众号 | 中 | 能证明近期办过活动 |
| 论坛、百科、聚合站 | 低 | 仅作辅助，不单独采信 |

### 4.3 从搜索结果提取什么

- 规范全名（含"酒店/度假村/会议中心"后缀）
- 详细地址（到门牌号）
- 电话（前台座机）
- 开业/翻新时间（老酒店影响体验）
- 宴会厅名称 + 面积 + 可容纳桌数（**这是 L4 的关键**）
- 客房总数
- 最近一条点评时间（越近越能证明在营）

## 五、误判排查清单

查到结果不等于查对了。以下六种情况必须逐条排掉：

| # | 误判类型 | 表现 | 排查方法 |
|---|---|---|---|
| 1 | **同名不同店** | "维也纳酒店"全国数千家 | 必须带城市 + 区，核对 `adname` |
| 2 | **同城多分店** | "XX 酒店（机场店）/（市中心店）" | 地址门牌号必须对上，不能只对品牌 |
| 3 | **已停业/装修** | API 仍返回 POI | 看点评最新时间，查是否有停业公告 |
| 4 | **换牌改名** | 原品牌已撤，现为其他品牌 | 名称相似度低但地址相同 → 按现名重查 |
| 5 | **集团品牌混用** | 万怡/万丽/万豪/万枫 傻傻分不清 | 逐个核对，不许"差不多就行" |
| 6 | **主体在但厅不在** | 酒店在营，宴会厅已改造成客房 | 查官网宴会/会议页面，或直接电话 |
| 7 | **子设施冒充主体** | 只找到「XX 酒店**洗手间**」「XX 酒店**停车场**」「XX 酒店-大堂」，却被当成酒店本身 | 脚本已内置拦截：剥掉设施后缀再比相似度，命中即判 ❌ 并提示换关键词 |

**第 3、6、7 条是最高频的真实翻车点。** 第 7 条尤其阴险——它在搜索结果里排名很靠前，不细看就会把「洗手间」当成酒店写进方案。

换关键词的标准动作：去掉城市前缀（"深圳观澜湖度假酒店" → "观澜湖度假酒店"），或用「品牌 + 区域」。实测前一种一换就中，能拿到真实电话和评分。

## 六、输出模板

核验完统一用这张表，一店一行，不许省略来源和日期：

| 名称 | 地址 | 电话 | 容量 | 报价区间 | 状态 | 来源 | 核实日期 |
|---|---|---|---|---|---|---|---|
| 深圳湾万丽酒店 | 南山区科苑南路 2601 号 | 0755-xxxxxxxx | 宴会厅 800㎡/50 桌 | ¥180-260/人 | ✅ | 高德 POI + 官网 | 2026-10-30 |

字段口径：

- **容量**：写「厅名 + 面积 + 可容纳桌数/人数」，不确定就写"未确认"
- **报价区间**：必须带口径（人均/桌/间夜/场次），带时间（"2026 年 10 月公开报价"）
- **来源**：写清是「高德 POI」「集团官网」「携程」还是「搜索交叉验证」
- **核实日期**：用当天日期，格式 YYYY-MM-DD

### 待确认清单

⚠️ 项单独再列一张，写明「要确认什么 + 建议怎么确认」：

| 点位 | 待确认项 | 建议确认方式 |
|---|---|---|
| XX 度假酒店 | 宴会厅实际可摆桌数 | 致电宴会销售，索取平面图 |
| XX 会议中心 | 2026 年 12 月档期 | 询价时同步问档期与定金比例 |

### 已排除清单

❌ 项也要留痕，避免下次重复踩坑：

| 点位 | 排除原因 |
|---|---|
| XX 国际会议中心 | 搜索无任何结果，疑为虚构名称 |
| XX 大酒店 | 2024 年起停业装修，暂无复业信息 |

## 七、几条实操经验

1. **电话是最硬的证据**。能打通、对方承认是这家酒店、能报出宴会厅，基本就没问题。方案里给电话比给地址有用。
2. **旺季核验要提前**。年会季（12 月-1 月）场地半年前就被订走，核验存在 ≠ 有档期，必须单独问档期。
3. **连锁品牌优先核验"哪家店"**。品牌存在毫无意义，要精确到门店。
4. **别信"XX 酒店集团"这种模糊表述**。要么写清具体门店，要么不写。
5. **核验失败的备选要同步准备好**。淘汰一个就要立刻有替补，不要让方案出现空洞。
